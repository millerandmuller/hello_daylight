# Research & Outreach Boundaries

Rules every Daylight run must follow before a draft reaches the user. If a rule fails, the item is dropped — not patched up.

## 1. Source relevance — what counts as a source

- [ ] The source is **public** and reachable by URL (forum thread, news article, blog post, public profile).
- [ ] It is **about the problem the project solves** — not just a keyword match on the project name or a generic term.
- [ ] It is **recent enough to act on**: a question still open, an article still current (default: last 90 days).
- [ ] The place **allows a reply or contact** in public (open thread, author contact shown on the page).
- [ ] The user's own links and findings always come first; wider search only adds to them, never replaces them.
- [ ] Not a source: paywalled or login-only content, private groups, scraped personal data, AI-generated content farms.

## 2. Factual accuracy — what must never be guessed

- [ ] Every card shows the **original link and date**, checkable in under 10 seconds.
- [ ] Never invented: names, quotes, numbers, dates, prices, product features, or claims about what the author said.
- [ ] Contact details are shown **exactly as published** — never guessed or derived (no "firstname@company.com").
- [ ] Claims about the user's project come only from the project page or what the user entered.
- [ ] If something can't be verified, the draft says so or leaves it out. Unknown stays unknown.
- [ ] Curated or example data is labeled as such — never shown as a live find.

## 3. Human approval — nothing goes out on its own

- [ ] Daylight **drafts, the human sends**. No posting, no DMs, no emails to third parties — ever.
- [ ] Drafts are delivered only to the workspace owner (clipboard + in-app inbox).
- [ ] Each draft is reviewed on its own card: **Sign / Edit / Thumbs up / Thumbs down**.
- [ ] The draft answers the question or reacts to the article first; the project comes second. No pitch-first messages.
- [ ] Before sending, the user checks: source opened? facts match? tone fits the place? Only then copy and post manually.
- [ ] Feedback (thumbs + comment) is stored and the next run shows what changed because of it.
